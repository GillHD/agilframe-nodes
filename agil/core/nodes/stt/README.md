# Отдельный узел распознавания речи

Контейнер `agil/node-stt:0.1.0` принимает аудио от Core и распознаёт речь через
`faster-whisper` на CPU. Он использует заранее подготовленный каталог модели,
подключённый только для чтения. Модель загружается в память перед запуском HTTP
сервера и переиспользуется для следующих запросов.

## Запуск

1. Подготовьте каталог модели CTranslate2. В каталоге должны быть `model.bin`,
   `config.json`, `tokenizer.json` и файлы словаря выбранной модели. Пользователю
   контейнера с UID 65532 нужен доступ на чтение.
2. В каталоге `agil/core/nodes/stt` задайте параметры в локальном `.env`.
   `STT_MODEL_DIR` содержит абсолютный путь к каталогу модели на хосте.
   `AGIL_STT_TOKEN` содержит отдельный секрет для запросов из Core.
   По умолчанию порт `8090` доступен на `127.0.0.1`. Для отдельного хоста задайте
   `STT_LISTEN_IP` на интерфейс, доступный Core.
3. Запустите `docker compose up -d --build` и проверьте `docker compose ps`.
   `/readyz` отвечает успешно после загрузки модели.
4. Укажите Core `STT_PROVIDER=remote`, `AGIL_STT_URL=http://127.0.0.1:8090/v1`
   и `AGIL_STT_KEY` с тем же значением, что и `AGIL_STT_TOKEN`. На отдельном хосте
   используйте его адрес. Core отправляет аудио по `POST /v1/audio/transcriptions`.
   Политика `PRIVACY_MODE=local` разрешает встроенный процесс `STT_PROVIDER=local`.

Воркер обрабатывает один запрос за раз, принимает до 9 МиБ на multipart-запрос
и до 120 секунд декодированного аудио. Результат содержит текст, язык и
временные границы сегментов. Модель и аудио остаются на вашем контуре.
Контейнер можно заменить с тем же каталогом модели без её повторного скачивания.

## Образ из реестра

Workflow `release-images.yml` собирает STT вместе с Core и нодой и публикует
его как `ghcr.io/<owner>/<repo>/stt` при выпуске версии. Для ручного прогона
workflow публикацию включает параметр `push`. Возьмите digest из отчёта
сборки и добавьте в `.env` значение `STT_IMAGE=ghcr.io/<owner>/<repo>/stt@sha256:<digest>`.
После подготовки модели и токена запустите `docker compose up -d --no-build`.

Для установки из панели загрузите тот же образ по digest на хост агента и
назначьте ему ожидаемый каталогом локальный тег. Укажите `STT_IMAGE_SOURCE=local`
в секции `stt` файла `module-env.json`.

```sh
docker pull ghcr.io/OWNER/REPO/stt@sha256:DIGEST
docker tag ghcr.io/OWNER/REPO/stt@sha256:DIGEST agil/node-stt:0.1.0
```

Проверьте в панели готовность воркера после загрузки модели. Документация
workflow описывает SBOM и проверку подписи образа. [Сборки](../../docs/ci.md).

## Установка через панель инфраструктуры

1. Подключите агент к Docker Engine на выбранной ноде. Подготовьте каталог
   модели на **хосте Docker** с доступом на чтение для UID 65532.
2. В файле `module-env.json` в каталоге состояния агента создайте секцию `stt`.
   Ограничьте доступ к файлу пользователем агента и задайте параметры из таблицы.
3. Подготовьте образ с тегом `agil/node-stt:0.1.0`. Если образ собран на ноде
   командой `docker compose build stt` или загружен через `docker load`, задайте
   `STT_IMAGE_SOURCE=local`. Если версия размещена в доступном ноде реестре,
   оставьте `pull`. Для этого способа запуска достаточно сборки образа без
   отдельного `docker compose up`.
4. В панели откройте «Инфраструктура» → нужная нода → «Модули». Нажмите
   «Установить» для STT и дождитесь статуса «Работает» и успешной проверки
   здоровья. Укажите URL и токен в Core как при запуске через Compose. Для
   проверки доступности по статусу ноды укажите её ID в редакторе организации
   в разделе «Сессия» → «Расшифровка».

| Поле секции `stt` | Значение |
| --- | --- |
| `STT_MODEL_DIR` | Абсолютный путь к подготовленной модели на хосте Docker. Агент монтирует его в `/models/whisper` только для чтения. |
| `AGIL_STT_TOKEN` | Отдельный токен для Core. Хранится на ноде. |
| `AGIL_STT_PREVIOUS_TOKEN` | Прежний токен, который воркер принимает во время обновления Core. После ротации удалите его. |
| `STT_LISTEN_IP` | IP для публикации порта 8090. По умолчанию `127.0.0.1`. Для Core на другом хосте укажите адрес приватного интерфейса. |
| `STT_DOCKER_NETWORK` | Имя созданной оператором приватной сети Docker. Если Core в той же сети, он может обращаться к воркеру по имени контейнера и порту 8090. |
| `STT_IMAGE_SOURCE` | `pull` по умолчанию или `local` для уже загруженного образа с тегом из каталога. |

«Перезапустить» сохраняет настройки и каталог модели. Для смены каталога,
адреса публикации или токена обновите локальный файл и переустановите модуль.

## Ротация токена воркера

1. На узле задайте новый токен в `AGIL_STT_TOKEN`, старый временно сохраните
   в `AGIL_STT_PREVIOUS_TOKEN`. В Compose эти значения читаются из `.env`.
   При управлении через агент задайте их в секции `stt` файла `module-env.json`.
2. Пересоздайте воркер с тем же томом модели. Дождитесь `/readyz`.
3. Обновите `AGIL_STT_KEY` на репликах Core. Проверьте распознавание из комнаты.
4. Уберите `AGIL_STT_PREVIOUS_TOKEN` и пересоздайте воркер ещё раз. Старый
   токен теперь должен получать HTTP 401. Проверьте новый токен и субтитры.

Воркер принимает прежний и новый токены, пока обновляются реплики Core.
Пересоздание единственного воркера может кратко прервать обработку. Для
непрерывной обработки обновляйте воркеры по одному с проверкой готовности.

## Проверка субтитров из браузера

Соберите Core, AI и демо. Для `node agil/core/qa/captions-e2e.mjs` задайте
`AGIL_QA_STT_WORKER_URL` с адресом воркера до `/v1` включительно,
`AGIL_QA_STT_WORKER_KEY` с тестовым токеном,
`AGIL_QA_STT_AUDIO` с путём к WAV с русской речью и
`AGIL_QA_STT_PHRASE` с фразой из WAV. Ключ `--recover-worker` имитирует один
HTTP 502 у отправителя и проверяет, что следующие фрагменты снова распознаются
и видны второму участнику. Ключ `--firefox-sender` включает отправку из Firefox
через Playwright. Получателем остаётся Chromium.
